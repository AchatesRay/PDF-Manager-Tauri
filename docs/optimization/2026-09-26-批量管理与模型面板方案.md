# 方案：PDF 重名跳过 + 列表批量管理 + 模型管理面板（2026-09-26 已确认）

> 用户确认的三个行为决策：
> 1. 重名处理：**跳过并汇总提示**（不中断其余导入，结束后一条汇总消息）
> 2. 重名判定范围：**同一文件夹内**（含根级 NULL，不同文件夹允许同名）
> 3. 模型启用/禁用：**切换当前识别模型**（启用=设为当前 OCR 模型；禁用=取消当前，文件保留不删除）

## 一、添加 PDF 按文件名去重（同文件夹）

**目标文件**：`src-tauri/src/commands/pdf.rs`

**原因**：现有 `add_pdf` 只按 `original_path` 查重，同名不同路径的文件会直接导入并被 UUID 改名，用户感知不到重复。

```diff
-    let existing: i64 = conn_check.query_row(
-        "SELECT COUNT(*) FROM pdfs WHERE original_path = ?1", ...);
-    if existing > 0 { return Err("该PDF文件已添加过") }
+    // ① 源路径查重（保留）
+    // ② 文件名查重：同文件夹（COALESCE 处理 NULL）内 filename 相同即重名
+    if existing_name > 0 { return Err(format!("文件名已存在: {}", filename)) }
```

**前端** `src/lib/components/PdfList.svelte` `handleAddPdf`：收集 `文件名已存在` / 其它错误，循环结束后用 `message()` 汇总「成功 N；跳过 M（重名清单）；失败 K」。

## 二、PDF 列表批量管理（多选 OCR / 删除 / 移动）

### 2.1 前端多选

- `PdfList.svelte`：header 增加「选择」切换；选择模式下显示批量操作栏（批量OCR / 批量删除 / 批量移动 / 全选 / 取消）。
  - 批量OCR：`pending` → `startOcr(id)`；`done/error` → `startOcr(id, true)`；`processing`/排队中 → 跳过。
  - 批量删除：一次 confirm 后循环 `deletePdf`，汇总提示。
  - 批量移动：弹文件夹选择对话框（复用 `$folders`）→ 调 `move_pdfs`。
- `PdfListItem.svelte`：新增 `selectable / checked / onToggle` 属性与 checkbox。

### 2.2 后端 `move_pdfs`

**目标文件**：`src-tauri/src/commands/pdf.rs`（新增）、`src-tauri/src/lib.rs`（注册）

```rust
#[tauri::command]
pub fn move_pdfs(pdf_ids: Vec<i64>, target_folder_id: Option<i64>, db, search_service)
    -> Result<MoveReport, String>  // { moved, skipped: Vec<(i64, String)> }
```

要点（防 P0-6 持锁死锁）：
1. 读完行立即 `drop(conn)`，锁外做文件操作；
2. 复用 `get_folder_storage_path` 计算目标目录；
3. 目标已有同名 → 跳过该文件计入 `skipped`（与功能 1 口径一致）；
4. `fs::rename`，跨盘回退 copy+delete；
5. `UPDATE pdfs SET folder_id, storage_path`；
6. **每个移动成功的 pdf 重建搜索索引**（`delete_pdf` + 从 `pdf_pages` 组 `PageIndexEntry` 重新 `index_pages`）——索引含 `folder_id`，不重建会导致按文件夹搜索错误。

## 三、模型状态面板

### 3.1 后端

| 文件 | 修改 | 原因 |
|---|---|---|
| `db/mod.rs` | 新增 `SETTING_OCR_ACTIVE_MODEL = "ocr_active_model"` | 启停需持久化 |
| `services/ocr_service.rs` | 字段 `active_model: Option<ModelType>`（默认 `Some(Balanced)`）；`get_status`/`init_ocr` 改用 active 文件清单（替换硬编码文件名）；`set_active_model()`（切换时 unload）；`OcrStatus` 增 `active_model` | 全链硬编码 Balanced，启停/切换无处落地 |
| `commands/ocr.rs` | ① `download_ocr_models`/`get_ocr_download_guide` 加可选 `model_type`；② 新增 `get_model_overview()`；③ 新增 `set_active_model(Option<String>)`；④ `start_ocr` 内存估算改用 active 模型 | 任选模型下载 + 启停；内存估算跟随实际模型（防「模型口径分裂」复发） |
| `lib.rs` | 注册新命令；setup 从 settings 读 active 模型应用到 OcrService | — |

`get_model_overview()` 返回 4 种 ModelType：`{ model_type, label, files[{name,url,size,downloaded}], ready, is_active, models_dir }`。

### 3.2 前端

- 新文件 `src/lib/components/ModelManagerPanel.svelte`：每模型一张卡片 — 文件清单（名/大小/已下载）、下载 URL（可复制/打开）、「下载」按钮（复用进度条事件）、启用/禁用开关；顶部显示当前启用模型与模型目录。
- `api/index.ts`：新增 `getModelOverview / setActiveModel / downloadOcrModels(type) / getOcrDownloadGuide(type)`。

## 兼容性注意（不影响已有功能）

- Mobile 与 Balanced 同文件是既有事实，默认 active = Balanced，老用户行为不变；
- `download_models`/`check_models` 本已按 `ModelType` 参数化，仅命令层去硬编码；
- 重名检查只**新增**约束，不改原 `original_path` 查重与存储改名兜底逻辑；
- 批量操作全部复用现有单条命令/新命令，不改单条操作路径。
