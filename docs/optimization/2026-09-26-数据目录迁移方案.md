# 方案：数据目录切换全量迁移 + 引导设置修复（2026-09-26 已确认）

> 用户确认的三个决策：① **全量迁移**（DB+pdfs+thumbnails+index+logs+models）② **日志写入跟随数据目录** ③ **目标目录已含应用数据 → 拒绝**。

## 根因（第一性原理排查）

1. `set_data_dir` 现状 = 校验 + 建空子目录 + 写设置，**零迁移**；子目录清单甚至不含 `models`。
2. **引导 bug**：重启时 `check_custom_data_dir`（`db/mod.rs`）**只读 exe 目录 DB 的 `data_dir` 设置**：
   - 第一次改目录 → 重启打开新目录**空 DB** → folders/pdfs/pdf_pages 全部「消失」（index 无回填数据源）；
   - 第二次改目录 → 设置写进当前 DB，重启只读 exe DB → **静默失效**；`reset_data_dir` 同理失效。
3. **日志实际写 exe 目录**（`lib.rs::init_early_logging` 用 `exe_dir/logs`），`get_settings` 却报 `data_dir/logs`——只迁内容不改写入位置，logs 迁完是死数据。
4. `pdfs.storage_path` / `folders.storage_path` 为绝对路径，不修正则迁移后文件「失联」。

## 修改

### ① `src-tauri/src/commands/settings.rs`（核心）

- 新增辅助：`normalize_dir`（去尾分隔符）、`copy_dir_recursive`（目录递归复制，子目录跳过已存在文件）、`fix_db_paths`（打开目标 DB 副本执行前缀替换）、`resolve_live_data_dir`（**用 `PRAGMA database_list` 取当前 DB 所在目录 = 真实活跃目录**，避免「设置值已指向新目录但数据仍在旧目录」的错位）、`finish_pending_data_dir_migration`（启动期刷新，见 ③）。
- `set_data_dir`：
  1. 校验（保留）；目标含 `pdf-manager.db` → 拒绝；
  2. 源 = `data_dir_migrate_from` 标记 ?? 当前 DB 目录；源==目标 → 跳过迁移只存设置；
  3. WAL checkpoint → 复制 db(+wal/shm)、pdfs/、thumbnails/、index/、logs/、models/（复制不删除，旧目录即备份；失败 → 不存设置，旧环境无损）；
  4. 打开目标 DB 副本：`UPDATE pdfs/folders SET storage_path` 前缀替换（`substr` 精确前缀，非 LIKE 通配）+ 写入 `data_dir` 设置；
  5. 设置**双写**（当前 DB + exe 引导 DB），并写 `data_dir_migrate_from=源目录` 到**引导 DB**。
- `reset_data_dir`：同时删引导 DB 的 `data_dir` 设置与 `data_dir_migrate_from` 标记（修复重置无效）。

### ② `src-tauri/src/db/mod.rs`

- 新增 `SETTING_DATA_DIR_MIGRATE_FROM` 常量（引导标记键）。

### ③ `src-tauri/src/lib.rs`（启动刷新 + 日志跟随）

- `run()` 在 `init_early_logging` **之前**调用 `settings::finish_pending_data_dir_migration(&exe_dir)`：
  - 引导 DB 有 `data_dir_migrate_from` 且 `data_dir` 存在且两者不同 → **刷新复制**（源→目标，db 覆盖、目录跳过同名）+ 路径修正 + 清标记。
  - **目的**：`set_data_dir` 与重启之间产生的新数据（新导入 PDF、OCR 结果、日志）在重启时补迁，消除「改完目录继续用产生的数据丢失」窗口；同时保证迁移失败时**回退引导设置到源目录**（应用继续用旧数据启动，不影响已有功能）。
- `init_early_logging` 改为接收日志基目录：`resolve_early_data_dir(exe_dir)`（引导设置 > 环境变量 > exe），日志写 `<data_dir>/logs`。

## 兼容与不回归

- 只复制不删除：任何时刻旧数据完好（红线备份要求天然满足）；
- 迁移失败路径：`set_data_dir` 不落设置；启动刷新失败回退引导设置 → 应用按旧目录正常启动；
- 88 个既有单测 + 新增迁移单测（临时目录：全量复制/路径修正/标记刷新/源==目标跳过）；
- 默认用户（从未改目录）路径零变化：无标记 → 无迁移，日志目录 = exe 目录 = 数据目录。
