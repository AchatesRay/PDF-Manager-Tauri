## 一、需求

1. 内容搜索后，右侧预览的**页面图像上**画出该页所有命中关键字的高亮框；
2. 「上一个 / 下一个」导航（或点击结果条目）时，**高亮焦点跟随切换**，自动滚动到当前命中位置；
3. 同页多处命中 → 焦点页内轮换；跨页命中 → 翻页后焦点落到新页对应位置；
4. 清除搜索隐藏高亮；手动翻页离开命页隐藏、翻回恢复。

## 二、根因分析

- 右侧预览是渲染后的位图（`render_pdf_page` → base64 PNG），无文本层 → 前端无法文本匹配定位，**必须有命中坐标**。
- 坐标 OCR 时已算出：`ocr_service.rs` 的 `OcrRegion{x0,y0,x1,y1,text,conf}`（整页坐标，分块合并后完整），但 `commands/ocr.rs::process_page` 落库只拼文本、**坐标被丢弃** —— 数据缺口是「算了但没存」。
- 搜索结果已有 `page_number + match_count + 页内序号`，导航骨架现成，只缺「页内序号 → 页面矩形」的翻译。
- 结论：补坐标数据管道 + 坐标查询命令 + 预览叠加层；**不动 OCR 模型、不动 Tantivy 索引**（索引版本不升级、无回填风险）。

## 三、数据流

```
OCR 落库：OcrRegion(像素坐标) ─归一化(÷图像宽高)─▶ pdf_pages.ocr_regions (JSON, 0~1)
导航时：  SearchResults ─invoke('get_page_matches', pdfId, page, query)─▶ 后端
            后端：读 ocr_regions → 区域文本内找 query → 子矩形(字符比例切分)
            返回 Rect[](0~1)（顺序=阅读顺序，与页内序号对齐）
PdfViewer：订阅 store → <img> 上按百分比定位叠加高亮框 → 焦点框 scrollIntoView
```

- 坐标存 0~1 归一化值：OCR 渲染尺寸（默认1000）≠ 预览渲染尺寸（2000），百分比与渲染/缩放/适应窗口全部解耦。
- 命中口径与搜索严格同源：`clean_ocr_text` 后按原始 query 子串匹配（同 `generate_snippet`）。

### 关键实现细节

- **子矩形切分**：OCR 行框内字符近似均匀，`x = x0 + (x1-x0)·i/len`，`w = (x1-x0)·qlen/len`；中文场景精度足够。
- **顺序对齐**：区域按阅读顺序（`merge_regions` 已排序）→ 高亮框序 = 结果列表页内序号。
- **高亮刷新位置**：在 `navigateToMatch` 的 pdf/page 变更 if **之外**，保证「同页翻下一个」也刷新 activeIndex。
- **隐藏条件**：`pageHighlight.pdfId/page` ≠ 当前展示的 pdfId/currentPage → 不渲染；不主动清 store（来回翻页不闪烁）。
- **文本生成保持不动**：仍是 `join("\n") + optimize_by_language`，落库文本与现行为等价（标点映射逐字符 1:1），加单测断言等价。

## 五、旧数据获取坐标（已确认：方案甲）

坐标缺失时 `get_page_matches` 返回 `[]` → 该页不高亮（不报错不崩）。
- **甲（首期采用）**：界面对该合同已有的「**强制重识别**」产出坐标 —— 零新代码零风险。
- 乙（二期可选）：`backfill_page_regions` 后台线程只补坐标不动文本/索引，观察后再加。

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 高亮框数 ≠ 结果 match_count | 两侧同用 `match_page_regions` 口径；单测断言相等 |
| 坐标与渲染尺寸不一致 | 归一化存储 + 前端百分比定位 |
| JSON 体积 | 每页 5–10KB，15 份合同 ≈ 2MB 内 |
| 动 OCR 文本路径回归 | `recognize_with_limit` 原签名原输出；等价性单测；现有测试全跑 |
| 锁序 | `get_page_matches` 只取 Db 锁 |
