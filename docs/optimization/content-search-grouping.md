# 内容搜索结果按 PDF 聚合 + 文件列表联动

## 现状

- 后端 `search` 按“页”返回命中（`pdf_id / page_number / match_count / snippet`，上限 50 条）。
- 内容搜索结果面板逐页平铺，同一 PDF 多页命中会重复出现多行。
- 点击结果只打开右侧预览并高亮，不联动中间 PDF 文件列表。
- 中间 PDF 列表受左侧当前选中目录筛选，跨目录命中文件不会被渲染。

## 目标

1. 内容搜索结果按 `pdf_id` 聚合，一个 PDF 一行：
   - 显示文件名、该 PDF 总命中数；
   - 片段显示“当前预览页”的片段，随上一个/下一个切换；
   - 去掉 `P3` 页码徽标。
2. 文件名列与片段列之间加可拖动分隔条，列宽写入 `localStorage` 持久化。
3. 点击结果行：
   - 右侧照旧打开预览并跳到命中页、画高亮；
   - 中间 PDF 文件列表定位到该文件：目标不在当前目录时自动切换到其所在目录，滚动到可见并短暂描边提示。

## 实现要点

- `SearchResults.svelte`：用 `Map` 按 `pdf_id` 聚合原始页级结果，保留页列表与首次出现的扁平索引，供上下条导航复用。
- 新增 store `revealPdfId`：搜索结果面板发出定位请求，`PdfList` 消费。
- `PdfList.svelte`：`tick()` 后按 `data-pdf-id` 查找行，`scrollIntoView` + 临时高亮 class。
- `PdfListItem.svelte`：根节点补 `data-pdf-id`。
- 不改后端搜索接口与索引结构。

## 验证

- `npm run build` 通过。
- 手工验证：多页命中同一 PDF 只一行；上下条切换时片段/高亮跟随；跨目录点击自动切目录并定位；列宽可拖且重开窗口保持。
